PMSS QA Verification — Code-Level Gauntlet for complete-verify Issues

NOTE: This is the CODE-LEVEL-ONLY QA prompt (runs inside codex exec, sandboxed).
Full end-to-end QA (SSH + service verification) runs externally when available.
This file is used as fallback when full E2E QA is not available.

Goal: Verify that issues labeled complete-verify are ACTUALLY fixed. Close if PASS.
Remove label and post failure report if FAIL. Attempt inline fix for simple failures.

This is the quality gate. Issues pass through here before being considered DONE.
No issue gets closed without passing this gauntlet.

VERIFICATION PROTOCOL
----------------------------------------------------------------------

For EACH complete-verify issue in context:

1) UNDERSTAND THE ISSUE
   - Read the issue title, body, acceptance criteria
   - Find the commit(s) that implemented it (search git log for "Refs #N")
   - Read the actual code changes: git show <commit>
   - Map acceptance criteria to code changes

2) LAYER 1 — STRUCTURAL TESTS (mandatory, instant)
   Run the full test suite ONCE for ALL issues in this batch (not per-issue).
   The baseline already ran these tests. Layer 1 verifies that implementing
   commits did not INTRODUCE new failures beyond the baseline.
   Run ALL of these ONCE:
     php -l <each changed .php file across ALL issues>
     php scripts/lib/tests/development/Runner.php
     scripts/testing/test-php.sh
     scripts/testing/test-bash.sh
     scripts/testing/php73-compat-scan.sh
     scripts/testing/php-lint-compat.sh
     scripts/testing/docblock-lint.sh
     scripts/testing/doctrine-lint.sh
   Also discover and run any additional test scripts: ls scripts/testing/
   Compare results against baseline. Any NEW failure (not in baseline) = ALL issues FAIL.
   If no new failures: ALL issues PASS Layer 1.
   NOTE: If the test suite has NO tests covering a specific change, state this
   explicitly in that issue's verification report: "No dedicated test coverage for <feature>."
   This is not a FAIL — but must be disclosed. The issue still passes if all other layers pass.

3) LAYER 2 — ACCEPTANCE CRITERIA MAPPING (mandatory)
   For each criterion in the issue:
   - Does the committed code ACTUALLY address it?
   - Not "looks like it should" — trace the exact code path
   - Read the actual source files, not just the diff
   - Check for edge cases the implementation might miss
   - QUOTE exact file:line for each criterion (e.g. "scripts/lib/sshd.php:142 sets Ciphers")

4) LAYER 3 — SECURITY REVIEW (mandatory for code touching user input)
   grep for risky patterns in changed files:
     grep -n 'exec(\|system(\|passthru(\|shell_exec(' <files>
     grep -n '@file_put_contents\|@file_get_contents\|@unlink' <files>
   Check: escapeshellarg on user input? No path traversal? No info disclosure?

5) LAYER 4 — SYMBOL REGRESSION CHECK (mandatory)
   If any functions/variables were renamed or deleted:
     grep -rn 'old_symbol' scripts/ install.sh
   ZERO hits required. Stale references = FAIL.

6) LAYER 5 — CROSS-FILE CONSISTENCY
   If templates were changed: verify config generation matches.
   If cron scripts changed: verify cron.d references.
   If update pipeline changed: verify step ordering.

----------------------------------------------------------------------
VERDICT RULES
----------------------------------------------------------------------

ALL layers pass?
  → PASS. Close the issue. Post verification report.

ANY layer fails?
  → Is the fix simple (< 20 lines, obvious, no architectural change)?
    YES → Fix it inline. Run full test suite. If passes: commit, re-verify.
          Max 2 inline fix attempts per issue.
    NO  → FAIL. Post failure report. Remove complete-verify label.

INLINE FIX PROTOCOL (when autocommit is active)
----------------------------------------------------------------------

If verification fails and the fix is simple:
1. Implement the fix (HARD LIMIT: 20 lines max. Count with `wc -l` on the diff.
   If diff exceeds 20 lines: it is NOT a simple fix. Post FAIL report instead.)
2. Run full test suite (ALL checks from Layer 1)
3. Run symbol regression check
4. If all pass: commit with "fix: <scope> — QA fix for #N (Refs #N)"
5. Re-verify from Layer 1
6. Max 2 attempts. After 2 failures: give up, post FAIL report.
