# ADR 0128: Pikkumies Eternals and account web UIs

Date: 2026-10-20
Category: architecture

## Status

Accepted. Ports A and B are gated by the host marker. Port C has a separate
account install gate.

## Context

Pikkumies keeps account-owned conversations alive through its per-minute cron
tick. Its simplified web UI needs a private service origin, while the panel is
shared among accounts. Root must not operate on paths controlled by an account
(ADR 0121). The panel, updater and account PHP run under different UIDs.
The exact cross-repository protocol is in `docs/contracts.md`.

## Options considered

- Give each account UI its own service origin and certificate.
- Put all UIs under one service port: Hermes cookies and incompatible backend
  paths would share a browser origin.
- Use fixed, separate service ports and an account-side launcher: each origin
  has one backend and a narrow launch contract.

## Decision

Ports 844, 845 and 846 belong to simplified Pikkumies, its Hermes dashboard,
and one selected vanilla Hermes UI, respectively. They are below port 1024.
A host-wide nginx default server rejects
unknown names on an enabled UI port. Account vhosts use only the service
permalink, a certificate issued for that name, exact Origin checks for writes
and upgrades, and a same-origin Fetch Site check on GET API requests. Port A's
`/bar` and outage page come from root-owned host files outside account homes.
The internal lighttpd UI mount is generated by PMSS, outside `custom.d`.
The shared panel's `/public-<user>/` and `/~<user>/` aliases reject every
`__pmss-ui-` internal mount before proxying to lighttpd.

The host marker `/etc/seedbox/config/pikkumiesEternals.enabled` gates
Eternals and ports A and B. Port C has an independent lifecycle. Removal of
the marker stops future convergence; it does not kill Eternals already running.
The marker is staged host by host. No enabled marker is shipped in the overlay.

The launcher is account-side PHP with no includes. It derives identity from
its effective UID, accepts only same-origin or `none` Fetch Site requests
(or an exact same-origin Referer when Fetch Site is absent),
and keeps A tokens in `L/ui/tokens/` with a 60-second lifetime and an eight
token cap. `?view=status` does not start a UI or mint a token. The launcher
requests a certificate only when DNS points to the current host and the
permalink fails TLS verification. Certificate flag changes run as the account.
The certificate job prefers root-owned provisioning state. Until a trusted
service ID has been written for an account, nginx and the certificate job keep
their former root-owned home-marker reads and warn once per account per run.
The provisioning marker CLI records both service and client IDs in the root
store. Once the trusted service ID is present, account-home billing files are
ignored for both names.

The panel adds a local Pikkumies tab after Welcome and a prompt bar in Welcome
only when the host marker, root-owned billing identity, account install, and
On state all exist. The bar stays disabled until the read-only status view
reports the UI ready; its root-owned page then stores a bounded pending-ask
queue on port A's origin and signals the panel with exact-origin messages.
The launcher identity artifact is published only on marked hosts as
`root:<account> 0640` under a root-owned traversal-only directory.
Configure presents a two-choice interface control. Power user retains the
same simplified tab and adds a new-tab launcher action for port B. The panel
never embeds B. Port B uses a separate account-owned Hermes process on its own
reserved loopback port. Its private credential file holds a random service
password and session secret, both separate from the account password. The
launcher reads the file only as the account, starts through `env -i` with an
exact public URL, and verifies both listener UID and HTTP login response before
redirecting. nginx permits only the Hermes login assets before an auth request,
rejects `/api/cron/fire`, checks GET API Fetch Site and exact write Origin, and
logs no query arguments. Port C uses the same clean-environment launch rule.
Configure reveals B's separate login password only after an account-password
challenge; its response is not cached or logged.
The account installs one tagged per-minute cron check when B first opens. The
check does not start a backend; it stops an owned listener that loses its login
gate. The launcher repeats the same check on each open. B's generated route
uses a Unix socket inside its private account directory. An account-owned relay
checks the TCP listener's UID before every connection and refuses a missing or
foreign listener. Logout and password change stop the simplified UI as the
account and rotate B's login password and session secret, plus C's session
secret. The account-side stop helper handles installed
Pikkumies versions whose `ui stop` command is absent.

The launcher displays the account memory floor when a v1 cgroup memory limit
is below 1000 MiB. An absent Hermes runtime gets a setup page; its button runs
Pikkumies' account-owned `post-update` setup under a lock. The setup action
does not run on a transfer hold or below the memory floor.

The Agentboard binary lives under a versioned root-owned `/opt` directory and
an atomically switched stable symlink. A version and SHA-256 pin are required
before installation; the host marker is also required. Empty pins or an absent
marker cause a logged skip. A stale version is quarantined under a root-only
directory before a verified replacement is published. The fork release uses the
`bun-linux-x64-baseline` target. The account launcher resolves the version once
for both the executable and its frontend directory. Account-owned Pikkumies
code schedules its
own cron tick through `Update::ensureScheduled`; PMSS does not introduce a
second root tick.

During transfer, source and target accounts apply `eternal hold --until` before
the final pass. The Pikkumies local directory is excluded from the hot main
pass, copied in the final pass, and the hold marker itself is excluded. On
success, the source sets `eternals.off` and remains held while the target
releases its hold and runs one ensure. On failure, the source releases its hold
and the target receives a long hold so a partial copy cannot auto-start when
the preparation hold expires. No root-owned transfer hold is used.
Recreate resets Pikkumies, Eternals
and Hermes state; the archived home retains their previous data.

## Consequences and limits

- The pinned Hermes release was checked against published upstream advisories.
  B and C require Hermes' login before any route opens. A uses a 256-bit bearer
  kept in a mode-0600 account file and carried in the URL fragment, which is not sent in HTTP
  requests or access logs. Primary account credentials are not stored by
  this feature. B and C use separate service credentials, session secrets,
  listener ownership checks and login gates. Exposure of a B or C service
  credential permits access to that account's agent UI, so its file is 0600,
  its value stays out of argv and logs, and the loopback listener is gated.
- UI authentication remains the access boundary: A has single-use bearer
  tokens, while B and C require Hermes' own login before their routes can open.
  Origin and routing checks provide additional protection.
- The static bar has no bearer or account credential. It can run only in a
  frame, and the existing frame-ancestor policy limits that frame to the panel
  origin. Questions and drafts stay in port A's browser storage; no question
  text is posted to the panel or written to PMSS logs. The interface choice is
  a private mode-0600 account file. The status response carries no bearer.
- Before each account's trusted provisioning write, nginx and the certificate
  job keep the previous root-owned home-marker read. Home markers never
  backfill the root store.
- The account's `.hermes` directory is excluded from the main transfer pass
  and copied in the final pass after the tracked dashboard stops.
- Account termination removes its certificate lineage after account removal.
- The launcher accepts same-origin panel requests; the account UI itself uses
  its single-use bearer.
- Hermes loopback listeners require an authenticated gate. B and C enforce it
  before launch and on each launcher access. Their sessions may share a browser
  cookie jar.
- Certificate Transparency records issued permalink names.
- The account Pikkumies updater follows its existing unsigned main channel.
  The Agentboard binary itself is pinned by SHA-256.
- The existing 1,000–3,000 certificates per registered domain per seven days
  quota and renewal exemption apply to implicit certificates (ADR 0039).
  About 2,331 services across 42 days mean roughly 390 new certificates per
  week at the staged pace. No new global quota counter is added.
